# Feature Specification: Post-Docking UX And Output Restructure

## Context

Recent interactive runs exposed usability and traceability issues:
- users get trapped in required prompts after analysis completion,
- protein/ligand naming prompts repeat across stage-only runs,
- stage outputs are scattered across many sibling folders with empty directories,
- progress visibility is weak for long-running analysis sequences,
- interaction visualization outputs are hard to read and hard to navigate.

This feature tightens the interactive workflow and restructures post-docking
output for better automation, readability, and scientific review flow.

## Functional Requirements

- FR-001: Interactive workflow panels must support safe cancel/back/exit flows
  so users cannot get trapped in required prompt loops.
- FR-002: Interactive analysis launches with multiple selected targets must
  write into one session-oriented analysis root instead of scattering outputs
  across many sibling target directories.
- FR-003: Protein and ligand display-name editing must be available as a
  standalone interactive action that is not coupled to running analyses.
- FR-004: Analysis logs must report deterministic step progress in the form
  `current_step/total_steps` so long runs expose completion status.
- FR-005: RMSD scope-signature generation must be deterministic and free of
  undefined-variable runtime failures.
- FR-006: ProLIF outputs must include both across-pose interaction artifacts
  and best-pose 2D interaction maps, organized under a clearer folder layout.
- FR-007: PoseView-only analysis targets must automatically enable PoseView
  execution so selecting that stage actually runs diagrams.
- FR-008: PyMOL interaction scripts must support a pocket-focused visualization
  style with readable residue labeling and avoid false-success messaging when
  the `pymol` executable is unavailable.
- FR-009: Consolidation must prune empty output directories generated by staged
  analyses to keep output trees understandable.
- FR-010: PandaMap output stems must avoid duplicated protein prefixes and
  produce one readable naming pattern per complex.
- FR-011: Post-docking visual outputs must be mirrored into canonical
  navigation roots (`visualizations/2d/...` and `visualizations/3d/...`) so
  users do not need to traverse tool-specific raw folders.
- FR-012: Consolidation must generate machine-readable visualization/raw-data
  manifests and a human-readable `START_HERE.md` navigation guide.
- FR-013: PandaMap publication analysis must emit 2D and 3D outputs under
  stable subfolders (`maps_2d` and `maps_3d`) with legacy-layout fallback
  support in downstream consolidation.

## Acceptance Criteria

1. `python main.py workflow interactive` no longer loops forever on required
   text prompts after repeated cancel events; users can return to menu/exit.
2. Selecting multiple analysis targets in one interactive run creates one
   timestamped session folder under post-docking `analysis/sessions/`.
3. A dedicated interactive stage can edit and persist protein/ligand display
   names without running any analysis.
4. Simplified pipeline logs include explicit `[n/N]` step markers.
5. RMSD analysis no longer raises `NameError: name 'scope_name' is not defined`.
6. ProLIF output includes:
   - across-pose barcode/network artifacts,
   - best-pose 2D maps,
   - a compact summary file under a single `interactions/prolif` tree.
7. Selecting `PoseView only` in interactive analysis triggers PoseView work
   without requiring an additional hidden flag.
8. If PyMOL is not installed, PyMOL stage outputs report skipped/missing state
   instead of claiming successful scene/session generation.
9. Consolidated output no longer accumulates stale empty directories after run.
10. PandaMap filenames do not contain duplicated `Protein__Protein__...`
    prefixes for the same complex.
11. Final output tree exposes canonical visual navigation under
    `visualizations/2d` and `visualizations/3d`, with interaction visuals grouped
    by tool.
12. Consolidation writes `raw_data/visualization_manifest.csv`,
    `raw_data/raw_artifact_inventory.csv`, and root `START_HERE.md`.
13. PandaMap analysis writes 2D/3D assets into `maps_2d`/`maps_3d` and pipeline
    compatibility code still recognizes legacy `2d_interaction_maps` /
    `3d_visualizations` directories when present.
