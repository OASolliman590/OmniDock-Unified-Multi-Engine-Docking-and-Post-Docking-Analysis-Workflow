# Current scientific preparation assessment

Repository: OmniDock, inspected at baseline `8d4434d3a33eb83b1e12cad82944b02c83270e47` on 2026-09-14. The earlier `audit/preparation-audit.md` and `docs/correctness-update.md` describe historical defects and their intended corrections; the matrix below records baseline residual risks. Row status text and the bounded-correction section identify changes now present in the working tree. It does not reclassify the historical fixes as current failures.

The primary sources establish the chemistry assumptions used here. Meeko requires explicit hydrogens and 3D coordinates for ligand input and rejects a molecule with more than one disconnected fragment at its molecule-setup seam [Meeko ligand preparation (2026/09), Command line script](https://meeko.readthedocs.io/en/develop/lig_prep_basic.html); [Meeko molecule setup (2026/09), `from_mol`](https://raw.githubusercontent.com/forlilab/Meeko/develop/meeko/molsetup.py). Meeko's receptor documentation describes template matching as a way to check heavy atoms, protonation, connectivity, bond orders, and formal charges [Meeko receptor preparation (2026/09), Overview](https://meeko.readthedocs.io/en/develop/rec_overview.html). PDB2PQR 3.7.1 exposes `--titration-state-method propka`, applies pH to the selected calculation, and executes PROPKA only when that method is selected [PDB2PQR main (2026/09), parser and `non_trivial`](https://pdb2pqr.readthedocs.io/en/latest/_modules/pdb2pqr/main.html); its algorithm guide lists PROPKA as the currently supported titration method and documents force-field-dependent unsupported states [PDB2PQR algorithms (2026/09), Titration state assignment](https://pdb2pqr.readthedocs.io/en/latest/using/algorithms.html). wwPDB defines `TER` as the end of a chain and `LINK`/`SSBOND` as connectivity annotations, with `CONECT` generated for disulfides when both sulfur atoms are present [wwPDB coordinate section (2026/09), `TER`](https://www.wwpdb.org/documentation/file-format-content/format33/sect9.html); [wwPDB connectivity section (2026/09), `SSBOND` and `LINK`](https://www.wwpdb.org/documentation/file-format-content/format33/sect6.html).

## Bounded correction order and ownership

1. **Receptor/structure worker:** `docking/preparation/structure_contract.py` (PREP-C05) and `docking/preparation/receptor_preparation.py` (PREP-C03, C04, C06), with `test/test_scientific_receptor_contract.py`. Preserve existing explicit backend failures and heavy-atom checks. Do not claim final pH, disulfide, metal, cofactor, or terminal equivalence without a state ledger.
2. **Ligand chemistry worker:** `docking/preparation/ligand_preparation.py` (PREP-C01, C02, C08), optionally a small identity helper and `test/test_scientific_ligand_contract.py`. The comparison must permit declared protonation/H changes while protecting heavy-atom connectivity and stereochemistry.
3. **Configuration/provenance worker:** `docking/models.py` and `workflow/reference_chemistry.py` for PREP-C07 and the remaining accession/selection/frame manifest gaps. The frame identifier should include source identity and selected atom mapping; a coordinate-only digest should not be treated as an accession/assembly/model identity.

The matrix deliberately does not prescribe a new pH threshold, tautomer enumeration policy, assembly, altloc, or metal/cofactor state. Those are experiment inputs. The implementable guards are finite-input checks, explicit state/provenance records, source-to-output mapping, preservation or rejection of authoritative connectivity, and fail-closed handling of unsupported transformations.
