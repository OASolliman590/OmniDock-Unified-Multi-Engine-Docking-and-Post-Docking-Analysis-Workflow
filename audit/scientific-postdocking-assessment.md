## Bounded action list

1. Fix exact record ordinals and strict PDBQT metadata scope in `post_docking_analysis/pose_geometry.py`, with parser-only fixtures that run without RDKit and separate chemistry fixtures for graph/stereo/mapping behavior.
2. Add a consensus input contract in `post_docking_analysis/consensus.py` that rejects ambiguous duplicate engine/tag rows and mixed scoring identities before normalization/pivoting. Preserve expected-engine denominator and missing-engine coverage behavior.
3. Add the corresponding one-row-per-engine/tag and score-direction/coverage fixtures in `test/test_scientific_consensus_contract.py`; add parser fixtures in `test/test_scientific_pose_records.py`. These tests should observe public functions and use literal independent expected outcomes.
4. Keep seed/replicate schema and report wording as explicit follow-up files unless the owning pipeline contract is updated together. No calibration model, physical validator, new threshold, remote benchmark, or alternative RMSD metric is justified by this audit.

## Proposed files and release checks

The bounded implementation owns `post_docking_analysis/pose_geometry.py`, `post_docking_analysis/consensus.py`, `post_docking_analysis/redocking_validation.py`, `test/test_scientific_pose_records.py`, `test/test_scientific_pose_chemistry.py`, `test/test_scientific_consensus_contract.py`, and `test/test_scientific_reference_contract.py`. An optional wording patch belongs in `post_docking_analysis/report_generator.py` only after confirming that this legacy generator is active in the canonical report route. The full release still requires real engine versions, repeated seeds, cross-docking, actives/decoys with leakage controls, RMSD/coverage/failure accounting, and uncertainty; those are benchmark work described in the correctness update, not inferred from local fixtures.
